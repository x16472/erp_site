# 題庫排序與附圖

MIS 題庫清單與題庫資料表檢視依編號的數值遞增排序，包含以文字儲存編號的相容資料庫結構，因此順序為 1、2、3、…、10、11。草稿、發布與停用題目共同依編號排序，可使用狀態篩選器縮小範圍。排序本身不變更既有編號；資料庫工具自行查詢時仍須指定數值排序。

舊版新結構各自透過 IDENTITY 與 SEQUENCE 產生 Id、QuestionNo，可能因快取或失敗寫入而出現不同的跳號。新版新結構的人工新增、來源匯入與預設題目新增，皆在交易內鎖定題目資料表，取得最大 Id 加一，同時寫入 Id 與 QuestionNo。失敗時不消耗下一個題號，並避免同時新增時重複取號。此流程需要服務帳號具備題目資料表的 INSERT、SELECT 與 ALTER 權限，因為會使用 IDENTITY_INSERT。鎖定期間會暫時序列化題目新增。

既有資料重編使用 `database/RenumberTrainingQuestions.sql`，不會由網站啟動時自動執行：

1. 先備份資料庫、停止網站及背景匯入，並結束尚未完成的作答。執行時使用 Company 資料庫與具備必要資料修改、ALTER 權限的管理連線。
2. 保持 `@Apply = 0` 執行預覽，核對舊 Id、舊 QuestionNo 與新編號對照。依既有 Id 遞增分配 1 至 N，包含軟刪除題目。
3. 核對後將 `@Apply` 改為 `1`，執行同一份腳本。腳本會保留其他題目欄位，同步更新答案、作答題目、錯題本與 SnapshotJson 的題目編號；重新驗證外鍵並檢查題目筆數及編號一致性，發生錯誤時回復交易。
4. 部署重新建置的 Go 程式與前後端修改，再啟動服務。原先開啟的題目編輯頁面須重新載入，避免以舊編號送出修改。

若只有截圖中的 12 筆題目，則 Id=1002、QuestionNo=51 的最後一筆會改為 Id=12、QuestionNo=12，後續新增為 13。若有其他資料引用題庫，或啟用中的觸發程序，腳本會停止，須先補齊對應處理。軟刪除保留編號；刪除題目後清單不會自動重編剩餘題目。人工以其他 SQL 新增資料也必須遵循相同編號規則。

在題目編輯區選取附圖後可預覽，按「儲存題目」才會上傳。支援 JPEG、PNG、WebP，檔案大小介於 128 Bytes 至 5 MB。更換與移除附圖也須儲存才會生效。編輯其他欄位時會保留既有附圖與程式碼區塊。

圖片存放於 `data/exam/images/`，服務會在第一次上傳時建立目錄。檔名使用關聯文件的主檔名；未指定文件時使用科目名稱，另加隨機識別碼及實際圖片副檔名，避免同題庫多張圖片互相覆寫。例如 `Python題庫_<識別碼>.png`。名稱中的空白與檔案系統不適用字元會轉為底線。

附圖檔名透過既有題目內容 JSON 儲存，不需要新增資料庫欄位。作答、成績回顧、錯題本與術科題目均會顯示附圖，讀取圖片須先登入員工入口。

部署時需重新建置 Go 執行檔以更新內嵌查詢目錄，並更新 Python 與前端檔案。服務帳號需有 `data/exam/images/` 的讀寫權限；備份時需包含該目錄。更換或移除附圖不會刪除舊圖片，讓既有作答快照仍可顯示原圖。
